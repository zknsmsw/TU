# 提瓦特交通联合

纯虚构的爱好者项目：以《原神》提瓦特世界观为背景的虚拟交通预订网站。与米哈游及任何现实运输系统无关。

## 当前进度

- ✅ 首页（导航栏 + 宣传图轮播，极简无废话）
- ✅ 账户系统（注册 / 登录 / 退出 / 修改密码；登录后点用户名弹出菜单）
- ✅ 订火车票（通勤线路、同名站自动换乘、站间票价计价、在线下单）
- ✅ 订高铁票（车次查询、每站累计票价、在线下单）
- ✅ 订机票（机场/航班管理、按机场名称或代码搜索、在线下单）
- ✅ 我的订单（火车票 / 高铁票 / 机票：下单 / 模拟支付 / 取消 / 退票）
- ✅ 后台管理（左侧分栏：线路管理 / 车次管理 / 站点管理 / 机场管理 / 航班管理 / 宣传图管理 / 票务设置 / 页脚声明）

## 第一次运行（只需做一次）

1. 先安装 Node.js（选 LTS 长期支持版）：https://nodejs.org/zh-cn
   安装时一路「下一步」即可。
2. 打开本文件夹，在地址栏输入 `cmd` 后回车（打开命令行窗口）。
3. 输入下面命令安装依赖（需要几分钟，联网）：

   ```
   npm run setup
   ```

4. 输入下面命令构建并启动网站：

   ```
   npm run go
   ```

5. 看到「后端已启动」提示后，打开浏览器访问：

   ```
   http://localhost:3001
   ```

## 以后每次启动

打开本文件夹 → 地址栏输入 `cmd` 回车 → 输入：

```
npm start
```

然后浏览器访问 http://localhost:3001

> 关掉命令行窗口 = 网站停止。想一直用就把窗口留着。

## 默认账号

- 管理员：首次启动时自动创建 `admin`，初始密码为**随机生成**（只会在启动日志里显示一次），登录后会被强制要求修改密码。也可以通过环境变量 `ADMIN_PASSWORD`（至少 8 位）指定初始密码。
- 普通账号：点右上角「登录 → 去注册」自己注册即可

> 安全配置（可选，均通过环境变量）：
> - `JWT_SECRET`：JWT 签名密钥（至少 32 位）。不设置时首次启动会自动生成随机密钥并保存到 `server/data/.jwt-secret`，请勿把该文件提交到版本库。
> - `CORS_ORIGIN`：允许跨域访问 API 的来源白名单（逗号分隔）。默认只允许同源访问。
> - `COOKIE_SECURE=1`：部署在 HTTPS 时给会话 Cookie 追加 Secure 标志。
> - `ADMIN_PASSWORD`：指定初始管理员密码。

## 火车票怎么计价

通勤车不计车次，只按线路走。票价 = 沿途各段「站间票价」之和：

- 每一段（相邻两站之间）可以单独设置票价；
- 某一段没单独设置时，使用「默认站间票价」；
- 两条线路经过同一个站名，就自动成为换乘站，查询时会自动给出换乘方案；
- **环线**：线路勾选"环线"后，末站会自动连回首站，形成闭环，可双向环绕乘车；环线首尾闭合的那一段同样可以单独设置票价。

后台管理里：**线路管理** → 展开一条线路，可维护站点顺序、每段的站间票价，并可勾选"环线"；**票务设置** → 设置默认站间票价。

## 高铁怎么计价

高铁按车次运行，不参与换乘。每个车次在每个经停站填一个「从始发站的累计票价」：

- A 站到 B 站的票价 = 到 B 的累计价 − 到 A 的累计价；
- 首站只填发车时间，末站只填到站时间，中间站填到站 + 发车时间；
- 查询：选出发 / 到达站，列出经过该区间的车次、时间、票价，可直接购票。

后台管理里：**车次管理** → 新建车次（车次号 / 担当企业），展开后可维护经停站顺序、到发时间和累计票价。

## 机票怎么计价

按航班点对点计价：后台「机场管理」添加机场（名称 / 2~4 位代码 / 城市），「航班管理」添加班次（航班号 / 起降机场 / 起飞降落时间 / 票价）。订票页输入**机场名称或代码**都能搜索到机场，选好起降机场即可查询航班并购票。

## 后台管理

用管理员 `admin` 登录后，点右上角用户名 →「后台管理」进入（普通用户看不到入口）。后台是左侧分栏导航，目前有：

- **线路管理**：增删线路、维护站点顺序、设置每段站间票价、填写担当企业
- **车次管理**：增删高铁车次、维护经停站顺序、到发时间、每站累计票价、担当企业
- **站点管理**：增删改站点（同名站 = 换乘站）
- **机场管理**：增删改机场（名称 / 机场代码 / 城市）
- **航班管理**：增删改航班（航班号 / 起降机场 / 起飞降落时间 / 票价 / 担当企业）
- **宣传图管理**：首页轮播图 + 导航栏标题图（Logo）（png / jpeg / gif / webp，≤ 5MB）
- **票务设置**：默认站间票价 + 退票手续费
- **页脚声明**：在网站底部版权声明下方追加 / 删除自定义声明（每条最多 200 字）

> 退票手续费支持三种：不收手续费 / 定额（固定摩拉）/ 百分比（按票价的百分比扣）；未设置则不收。已支付订单在「我的订单」里可退票。

上传的图片保存在 `server/uploads` 文件夹，导航栏与首页即时读取，无需重新构建。

## 数据存在哪

所有数据保存在 `server/data/db.json`（纯 JSON 文件，零依赖，任何电脑都能跑）。之后功能做完可以平滑换成 SQLite / MySQL。

## 常见问题

- **提示「网络错误」或页面能开但登录没反应**：后端没启动，先运行 `npm start`。
- **改了代码后页面没变化**：重新运行 `npm run go`（重新构建前端）。
- **想清空数据重新开始**：删除 `server/data/db.json` 后重启即可。
- **安装时报 `esbuild ... EFTYPE` 或一堆 `EPERM` 警告**：esbuild 的二进制文件没装完整，通常是杀毒软件或 OneDrive 同步在锁文件。解决办法：
  1. 关闭所有其他终端窗口（确保没有 node 进程在跑）。
  2. 删除装坏的目录：`Remove-Item -Recurse -Force .\client\node_modules` 和 `Remove-Item .\client\package-lock.json`（文件删不掉就先暂停 OneDrive 同步或重启电脑再删）。
  3. 重新安装：`cd client` 后 `npm install`。
  4. 若仍报 esbuild 错：`npm cache clean --force`，再 `npm install -D esbuild --force`。
  5. 回到根目录 `cd ..`，重新 `npm run go`。
- **Node.js 版本很新（非 LTS）**：构建工具偶尔对新版本支持不稳，若反复出问题建议安装 LTS 版本（22 或 24），可用 nvm-windows 切换。
- **项目在桌面 + 开了 OneDrive 同步**：`node_modules` 文件极多，OneDrive 同步容易导致安装/启动各种奇怪错误。强烈建议把项目挪出桌面（如 `C:\dev\TU`）。
